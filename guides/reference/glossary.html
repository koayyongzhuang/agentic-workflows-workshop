Lab guides/Reference

Reference

Glossary

The words the guides use, and the one meaning each has here. Where the field uses several words for one idea, the guides stick to the first.

Agents

Agent
A model in a loop that decides for itself which tools to call and when to stop. In this workshop, not a synonym for "chatbot" or "workflow".
Workflow
Models and tools connected by a path fixed in code. The five patterns are workflows; Lab 1 is an agent.
Tool
A Python function the model may ask to run. The model sees only its name, docstring and argument types. Avoid: function call, plugin.
Tool call
The model's request to run a tool with specific arguments. Your code runs it, not the model.
Prompt
Short for system prompt: the instructions the model reads before every conversation (PROMPTS in Lab 1). It shapes how the agent behaves but can't stop it calling a tool it has.
Role
A named pair of one prompt and one tool list (ROLES in Lab 1). A tool that isn't in the list can't be called at all.
Specialist
An agent with a narrow job and few tools, such as validation_agent. Avoid: sub-agent, worker (worker means a Pattern 4 copy).
Supervisor
The agent in Lab 2 that picks the next specialist after each report, until the request is handled.
Structured output
A model reply forced into a fixed shape, such as the Route or Intent model, so code can use it safely.
Mock model
The offline stand-in (MODEL=mock) that picks tools by keywords. It shows the mechanics but ignores prompts.

LangGraph

Graph
Nodes connected by edges, sharing one state. compile() turns it into something you can invoke.
State
The shared data every node reads and updates, declared as a typed class such as PipelineState.
Node
A function that takes the state and returns an update to it. It may call a model, or just run code.
Edge
A fixed connection: after node A, run node B.
Conditional edge
A function that reads the state and returns the name of the next node. Avoid: router (the router is the node that decides).
Reducer
The rule for combining updates to one state field. Without one, the last write wins; with operator.add, lists are appended.
Super-step
One round of execution. Nodes in the same super-step run concurrently.
Send
An instruction to run a node with its own input. Returning several starts several copies (Pattern 4).
Subgraph
A compiled graph used as a node inside another graph.
Checkpointer
Saves the state after every step, per thread. In Docker it saves to PostgreSQL.
Thread
One conversation's saved history, named by thread_id. Open a new thread in Studio, or type /new in the terminal chat.
Interrupt
A pause inside a node (interrupt()) that waits for outside input, resumed with Command(resume=…).

Memory and knowledge

Short-term memory
The current thread's messages, kept by the checkpointer.
Long-term memory
Facts kept across threads in the vector store (remember_fact, recall_facts).
RAG
Retrieval-augmented generation: search the knowledge base, then give the matching text to the model.
Embedding
A list of numbers that represents a text's meaning, so similar texts can be found. hash embeddings are the offline, keyword-like option.
Knowledge base
The fictional scheme documents in data/knowledge_base/.

Guardrails

Guardrail
A rule enforced in code, outside the model, that limits what an agent sees or does. A rule written only in a prompt is an instruction, not a guardrail.
PII redaction
Replacing personal identifiers (NRIC, card, email, phone, bank account) before a model sees them.
Prompt injection
Input written to make the model ignore its instructions, such as "ignore previous instructions". OWASP LLM01
Allow-list
The tools each agent may call (TOOL_ALLOWLIST). Anything not listed is denied.
Policy
A condition checked on every tool call (check_policy): no booking or submission before validation.
Human approval
An interrupt that waits for a person's yes before a booking or submission runs.
Validated scheme
A scheme the applicant passed check_eligibility for, kept in validated_schemes.

Running and observing

Trace
The record of one run: nodes visited, tool calls, model calls and time. Printed live and saved to traces/traces.jsonl.
Studio
LangSmith Studio, a web view of the graphs served by make studio, where the labs run. It draws the graph and shows every step of a run. Needs a free LangSmith account and Chrome; without it, use the "No Studio?" boxes in the guides.
Assistant
In Studio, a graph plus saved settings, such as Lab 1's Lab 1 · A · prompt: concise. Click one in the Assistants panel and turn on Active; new threads use the active assistant. Default Configuration is the graph with no extra settings.
Container shell
A terminal inside the workshop container, opened with make shell. The python -m … commands in the "No Studio?" boxes run there.

Definitions follow the LangGraph Graph API overview and Building Effective AI Agents.
