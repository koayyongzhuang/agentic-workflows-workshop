Run the labs without Docker or Podman

Can't install a container engine on your laptop? You can run Labs 1, 2 and 3 with uv instead. This page replaces steps 1 to 4 of Before you start.

You need
uv, a web browser
Works for
Labs 1, 2 and 3
Not for
Lab 4 (Hermes)

By the end

uv run python -m scripts.check_setup shows every line green, Studio is open in your browser, and you can follow every guide using the commands on this page.

What changes without containers

The labs can run inside one Python process, with nothing else to start:

  • Database: the knowledge base and agent memory are kept in memory instead of in PostgreSQL. They're rebuilt every time you start a lab, and saved conversations are gone when you stop it.
  • Mock Gov API: it runs in-process, so you don't start it separately.
  • Commands: instead of make …, you put uv run in front of the Python command (table below). "Container shell" in the guides means your own terminal in the repo folder.

Everything else is the same: Studio, the graphs, the exercises and the quizzes.

Set up

  1. Install uv

    uv installs Python and the workshop's packages, and runs every lab command. You don't need to install Python, Git or make. You also need a web browser and a free LangSmith account, the same as in the main setup.

    macOS or Linux 
    $ curl -LsSf https://astral.sh/uv/install.sh | sh

    On a Mac you can use Homebrew instead: brew install uv.

    Windows 10 or 11 
    winget install astral-sh.uv

    Use PowerShell for every command on this page.

    Close the terminal and open a new one, then check that it finds uv:

    $ uv --version
  2. Get the repo

    No Git? Open the workshop repo's page on GitHub, click Code → Download ZIP, and unzip it. Without containers, the ZIP works fine.

    Then open a terminal in the unzipped folder, the one with pyproject.toml in it. Every command on this page runs there.

  3. Install Python and the workshop's packages
    $ uv sync --python 3.12 --extra openai --extra dev

    It takes about a minute. uv downloads Python 3.12 if you don't have it and puts it, with every package, in a .venv folder in the repo. Nothing else on your laptop changes. openai is the client for the workshop's Bifrost gateway, and dev adds Studio and the tests.

    No activating. uv run uses the repo's .venv for you, in any new terminal, as long as you're in the repo folder.

    Using a different provider from .env.backup, such as Bedrock directly? Add --extra all.

  4. Create your settings file

    Same as the main setup: copy the example, then fill in BIFROST_API_KEY (collect yours at stack.asean-lab.com) and LANGSMITH_API_KEY.

    $ cp .env.example .env

    Don't add a DATABASE_URL or GOV_API_URL line, or leave them empty. When they're empty, the labs use the in-memory database and the in-process API.

  5. Check it
    $ uv run python -m scripts.check_setup

    Every line should show a green ✓. These three lines confirm you're running without containers:

    ✓ Mock Gov Service in-process: … schemes
✓ RAG store in-memory, embeddings 'hash', …
✓ checkpointer InMemorySaver

    If "LLM responds" fails, fix MODEL or the key in .env and run the check again. You don't need to restart anything: .env is read each time a command starts.

  6. Open Studio

    Studio needs two terminals in the repo folder. In the first, start the Studio server and leave it running:

    $ uv run python -m scripts.studio_dev --port 2024 --no-browser

    In the second, create the Lab 1 assistants. Leave it running as well, so new roles you add appear in Studio:

    $ uv run python -m scripts.studio_assistants --wait --watch

    Then open https://smith.langchain.com/studio/?baseUrl=http://127.0.0.1:2024 in your browser and click Allow if it asks to connect to your local server. Safari can't connect to the local server, so use another browser.

Use these instead of the guide's commands

Where a guide says make something, run the matching uv run command in a terminal in the repo folder.

The guide saysRun this instead
make checkuv run python -m scripts.check_setup
make studioThe two terminals in step 6
make singleuv run python -m lab_1_single_agent.run
make patterns P=…uv run python -m lab_2_multi_agent.patterns.run …
make multiuv run python -m lab_2_multi_agent.citizen_platform.run
make serveuv run uvicorn lab_2_multi_agent.citizen_platform.serve:app --port 8080 --reload
make deepuv run python -m lab_3_deep_agent.run
make tracesuv run python -m scripts.trace_report
make shell, then python -m …Skip make shell. Run uv run python -m … in your own terminal.

For make patterns, put the pattern name where the … is, for example pattern_2_routing, or all for all five. Options such as --role eligibility_checker or -q '…' go at the end, the same as in the guides.

The tests (make test) run with the offline mock model:

macOS or Linux 
$ MODEL=mock EMBEDDING_MODEL=hash VERBOSE=false uv run pytest
Windows (PowerShell) 
$env:MODEL="mock"; $env:EMBEDDING_MODEL="hash"; $env:VERBOSE="false"; uv run pytest

These settings last until you close PowerShell. Open a new one before you go back to a real model.

Not needed without containers

The guide saysDo this instead
make up, make up-build, make down, make logsNothing. There are no containers to start or stop.
make restart-api (Lab 1, Exercise D)Studio reloads on its own when you save workshop/gov_api/data.py. In a terminal chat, type /exit and start it again.
make ingestStop the lab (or Studio, with Ctrl+C) and start it again. The knowledge base is rebuilt the first time it's searched.
make clean-dbStop and start the lab or Studio. In-memory data is gone when the process stops.

Lab 4 · Hermes Agent

Lab 4 is built for the container. Hermes gets its own Python environment and Node.js 22 there, and its shell commands can only reach the repo. Without the container, pair up with someone whose containers run, or watch the facilitator's demo.

Advanced: run Hermes natively (macOS or Linux)
Know this first. Without the container, Hermes's shell commands run directly on your laptop, not in a sandbox. It still asks before risky commands.
  1. Install Node.js 22.
  2. Install Hermes as its own tool, separate from the workshop's packages: 
    $ uv tool install --python 3.12 "hermes-agent[web,mcp,pty,cron,cli]==0.19.0"
  3. Copy lab_4_hermes/config.yaml and lab_4_hermes/SOUL.md into ~/.hermes/. In the copy of config.yaml, replace the three placeholders and the folder:
    • ${HERMES_MODEL} → bedrock/global.anthropic.claude-haiku-4-5-20251001-v1:0
    • ${HERMES_PROVIDER} → bifrost
    • ${HERMES_BIFROST_BASE_URL} → your BIFROST_URL with /v1 on the end
    • cwd: /app → the full path of your repo folder
  4. In the repo folder, start the tools server: 
    $ uv run python -m workshop.mcp_server --port 8765
  5. In another terminal, export HERMES_HOME=~/.hermes, your BIFROST_API_KEY, and the three HERMES_DASHBOARD_BASIC_AUTH_* values from lab_4_hermes/start.sh. Then start the scheduler and the dashboard, and sign in at http://localhost:9119: 
    $ hermes gateway run &
$ hermes dashboard --port 9119 --no-open --skip-build

When something goes wrong

You seeDo this
uv not foundClose the terminal and open a new one, so it picks up uv. Still missing? Run the install from step 1 again.
No module named 'workshop'You're not in the repo folder, or you left out uv run. cd to the folder with pyproject.toml and put uv run in front.
No module named 'langchain_openai'Run the uv sync command from step 3 again, with both --extra options.
An install fails while building a packageuv picked a Python that's too new. Run step 3 again with --python 3.12.
"Mock Gov Service" shows an http:// address, not in-processYour .env has a GOV_API_URL. Empty it. Do the same for DATABASE_URL.
Studio says Port 2024 is already in useAn earlier Studio (or the containers) is still running, so Studio picked another port and the Studio link won't connect. Stop the old one with Ctrl+C in its terminal, then start Studio again.
Port 8080 is already in useAn earlier serve is still running. Stop it with Ctrl+C in its terminal.
The agent forgot an earlier conversationExpected: memory is in-memory, so it's cleared when you stop the lab or Studio.
A new knowledge-base file isn't foundStop and start the lab or Studio, so the knowledge base is rebuilt.
