Lab guides/Reference

Reference

Commands

Every command the guides use, in the order you'll need them.

Where to type

Laptop terminal: a normal terminal in the repo folder. All make commands run here.
Studio: run make studio, then open it in Chrome. The labs run here.
Container shell: open it with make shell. With make single and make multi, the python -m commands are the no-Studio way to do the same steps.

Set up and check

Laptop terminal

make upStart the database, the Mock Gov API and the workshop container. Builds them the first time only.
make up-buildRebuild the containers, then start them. Use after the repo's dependencies change.
make checkPre-flight check of the model, tool calling, API, RAG and memory. Every line should be green.
make shellOpen the container shell.
make clean-dbEmpty the database (knowledge base, long-term memories, saved conversations) and clear Studio's saved threads. Stop make studio first. The knowledge base reloads on the next search.
make logsFollow the containers' logs when something won't start.
make downStop everything at the end of the day.

Lab 1 · Single agent

Laptop terminal

make singleNo Studio? Chat with the single agent in the terminal instead.

Container shell

python -m lab_1_single_agent.run --role helpdesk -q 'What schemes are available?'
Add this optionTo
-q '…'Ask one question and exit.
--prompt strict_officerUse a different system prompt.
--role eligibility_checkerUse a role: a prompt plus its own tool list.
--show-graphPrint the graph as a Mermaid diagram.

Inside any chat

Type at the you › prompt

/newStart a new thread. Short-term memory is cleared.
/graphShow the graph.
/exitLeave the chat.

Lab 2 · Patterns and platform

Laptop terminal

make patterns P=pattern_1_sequential_pipelineNo Studio? Run Pattern 1 · Sequential Pipeline in the terminal.
make patterns P=pattern_2_orchestratorNo Studio? Run Pattern 2 · Orchestrator in the terminal.
make patterns P=pattern_3_parallel_fan_out_gatherNo Studio? Run Pattern 3 · Parallel Fan-Out / Gather in the terminal.
make patterns P=pattern_4_hierarchical_decompositionNo Studio? Run Pattern 4 · Hierarchical Decomposition in the terminal.
make patterns P=pattern_5_generator_criticNo Studio? Run Pattern 5 · Generator & Critic in the terminal.
make multiNo Studio? Chat with the Citizen Services Platform in the terminal instead. You approve bookings.
make testRun the offline test suite after you change code.
make tracesSuccess rate, response time and most-used tools across your runs.
make serveServe the platform as an HTTP API on port 8080.

The P= value is the same as the pattern's Studio graph name and file name. Plain make patterns runs all five in a row. In Studio, pick the graph with that name instead.

Container shell

python -m lab_2_multi_agent.patterns.pattern_2_orchestrator 'I disagree with my rejection'
python -m lab_2_multi_agent.citizen_platform.run --auto-approve -q '…'
python -m lab_2_multi_agent.citizen_platform.run --show-graph

When something goes wrong

Dollar signs

Wrap questions in single quotes. In double quotes the shell turns $2,400 into ,400.

Don't pass dollar amounts through make … ARGS= either: make expands $ too. Use the container shell instead.

You seeDo this
"LLM responds" fails in make checkFix MODEL or the API key in .env, then run make up so the container reloads it.
service "workshop" is not runningRun make up. If it still stops, read make logs.
A Studio run fails with "model busy", 429 or a timeoutWait a few seconds, then submit again. Free models share one rate limit, so this happens more often on them.
The terminal chat says "The model is busy" or "Couldn't reach the model provider"Wait a few seconds, then press Enter at the you › prompt to retry the same question. Free models share one rate limit, so this happens more often on them.
Prompt changes do nothingYou're on MODEL=mock, which ignores prompts. Switch to a real model.
Studio won't connectUse Chrome, sign in to LangSmith, and keep make studio running. Still stuck? Skip Studio; the terminal shows the same path.
The wifi is downSet MODEL=mock in .env. Every graph still runs offline.
