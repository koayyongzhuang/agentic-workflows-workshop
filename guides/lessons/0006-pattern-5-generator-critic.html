Generator & Critic Editor's Desk

One agent writes. Another checks the draft against explicit criteria and sends it back with feedback until it passes or runs out of rounds.

By the end

You've capped the loop at one round, seen what the graph hands back when the critic says no, and watched the critic's feedback fix the draft when another round is allowed.

The scenario

The agency texts seniors a reminder before their home mobility assessment. Every SMS has to pass five rules (the CRITERIA in the file): length, the date and purpose, how to reschedule, no personal identifiers, and plain language. A generator writes a draft, a critic checks it against the rules, and the draft goes back with feedback until it passes or runs out of rounds.

You give itA task: what to write.
It producesThe latest draft, whether it was approved, the critic's feedback, the round number and a history of every round.
Calls a modelgenerator and critic, once each per round, for at most 3 rounds (MAX_ROUNDS).

The idea

Also called evaluator-optimizer. Use it "when we have clear evaluation criteria, and when iterative refinement provides measurable value." Source

The critic returns a Critique: approved (true or false) and feedback. A conditional edge then decides whether to loop back:

def loop_or_stop(state: GCState) -> Literal["generator", "__end__"]:
    return END if state["approved"] or state["round"] >= MAX_ROUNDS else "generator"

One detail is easy to miss. The critic's message says Draft (N chars), counted by Python with len(). Models are poor at counting characters, so the code measures and the model judges.

Other use cases

Write, check against clear rules, revise, with a cap on rounds. The same shape shows up well outside citizen services:

Use caseWhat it looks like
Code with testsThe generator writes the function; the critic runs the tests and sends back the failures.
Tender or grant proposalThe critic scores each draft against the published rubric and says which criterion is weak.
Marketing copyThe critic checks brand voice and flags claims legal hasn't approved.
TranslationThe critic compares the translation with the original and flags meaning that got lost.

Not the right fit? The critic needs rules it can check, like this SMS's five. Give it a vague goal such as "make it better" and it finds something new to change every round: you pay for two more calls each time, and each rewrite can drop details that were fine.

Do it

  1. Run it in Studio and watch the loop
    What you're testing. Whether specific feedback from a second model actually improves the draft, round by round.

    In Studio, pick pattern_5_generator_critic. Paste this into the task field and submit:

    Write an SMS (max 300 characters) reminding a senior of their home mobility assessment tomorrow at 10:00.

    Step through the run and watch round, approved and feedback change each time the graph passes through critic. Read the feedback: is it specific enough to act on?

    No Studio? Use the terminal instead 
    $ make patterns P=pattern_5_generator_critic

    After the final draft, the history prints each round's draft and critique.

  2. Allow only one round
    What you're testing. What the graph hands back when the critic says no and there are no rounds left.

    In pattern_5_generator_critic.py, make two changes. Cap the loop at one round:

    MAX_ROUNDS = 1

    And add a sixth line to CRITERIA:

    6. Gives the reschedule hotline 1800-555-0123.

    Save. Studio reloads the graph. Open a new thread and submit the same task.

    No Studio? Use the terminal instead 
    $ make patterns P=pattern_5_generator_critic
    Predict Does the SMS pass? What does the run return?

    It fails. Only the critic is given CRITERIA; the generator sees just the task, so it can't know the hotline number. With MAX_ROUNDS = 1, loop_or_stop ends the run straight after the critic says no. The final state has approved: false, the critic's feedback ("add the hotline 1800-555-0123") and a draft that was never fixed. The graph doesn't raise an error: your code must check approved and decide what to do, for example send the draft to a person.

    Now set MAX_ROUNDS back to 3, open a new thread and submit the task again.

    Check What changed?

    Round 1 still fails, but this time the loop goes back to generator with the feedback, and round 2 includes the hotline and passes. The critic's feedback is the only way the rule reached the generator.

  3. Find the brakes
    What you're testing. Why every cycle needs its own cap.

    Open loop_or_stop in pattern_5_generator_critic.py.

    Think If you deleted or state["round"] >= MAX_ROUNDS, what would stop the loop?

    Only the critic saying yes. If it never does, LangGraph's own recursion limit would eventually stop the run with a GraphRecursionError.
