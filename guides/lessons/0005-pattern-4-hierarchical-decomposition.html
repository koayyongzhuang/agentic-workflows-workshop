Hierarchical Decomposition Russian Doll

A planner breaks a big goal into sub-tasks and starts one worker for each. Each worker is a small graph of its own.

By the end

You can predict how many LLM calls a run will make from the planner's output, and you've changed the cap that keeps cost under control.

The scenario

A community centre volunteer asks for one briefing on all the support a resident could get. Nobody knows in advance how many schemes that covers. A planner reads the goal and splits it into research sub-tasks; one worker per sub-task looks up the policy and summarises it; an aggregator puts the findings together into one briefing.

You give itA goal: what the briefing should cover.
It producessubtasks (the plan, at most four), findings (one per worker) and the final briefing.
Calls a modelplanner, then summarise inside each worker (its research step only searches), then aggregator: N + 2 calls for N sub-tasks.

The idea

Also called orchestrator-workers by Anthropic and LangGraph. It fits "complex tasks where you can't predict the subtasks needed." Source

In Pattern 3 the three reviewers were written into the graph. Here nobody knows in advance how many sub-tasks there will be; the planner decides at run time. Two LangGraph features make that work:

  • Send. The delegate function returns one Send("worker", {"subtask": …}) per sub-task, so LangGraph starts that many copies of worker, each with its own input.
  • A subgraph as a node. worker is a compiled graph (research → summarise) added with g.add_node("worker", build_worker()). That is the doll inside the doll.

Do it

  1. Run it in Studio and open the inner doll
    What you're testing. How a plan made at run time turns into work: one worker, and one model call, per sub-task.

    In Studio, pick pattern_4_hierarchical_decomposition. Paste this into the goal field and submit:

    Prepare a one-page briefing for a community centre volunteer on ALL support a 70-year-old resident living alone on $1,200 a month could get, and how to apply for each.

    Click planner to see the subtasks it chose. The worker node is a subgraph: expand it to see research → summarise, and watch several workers run at once.

    Predict If the planner made 3 sub-tasks, how many LLM calls did the run make?

    Five: 1 planner + 3 workers (only summarise calls a model; research is a search) + 1 aggregator. In general that's N + 2.

    No Studio? Use the terminal instead 
    $ make patterns P=pattern_4_hierarchical_decomposition

    The last line tells you what the planner did: Planner created N sub-tasks; N workers reported. Compare N + 2 with the trace's "LLM calls" count.

  2. Make the goal bigger
    What you're testing. What stops a planner that decides at run time from creating unlimited work.

    Give the planner a goal that touches more schemes. Open a new thread, paste this into goal and submit:

    Prepare a briefing on ALL support a household could get: two grandparents aged 68 and 72, two working adults earning $5,500 a month together, one adult who wants to retrain, and a family that plays sport.
    No Studio? Use the terminal instead

    Replace GOAL in pattern_4_hierarchical_decomposition.py with the text above, then:

    $ make patterns P=pattern_4_hierarchical_decomposition
    Check Did the number of sub-tasks go up? What stops it growing without limit?

    The planner probably asked for more sub-tasks, but you'll never see more than four workers: planner returns plan.subtasks[:4]. That one slice is the cost control. Every extra sub-task is one more LLM call, and with a real planner a vague goal can produce a lot of them.

  3. Tighten the cap
    What you're testing. The trade-off between cost and completeness.

    Change plan.subtasks[:4] to plan.subtasks[:2]. Save. Studio reloads the graph; if it doesn't, restart make studio. Open a new thread and submit the bigger goal again. Read the briefing: what's missing now? Decide which you'd rather have in production, a cheaper briefing or a complete one, and put the cap back where you want it.

    $ make patterns P=pattern_4_hierarchical_decomposition
