Hierarchical Decomposition Russian Doll

A planner breaks a big goal into sub-tasks and starts one worker for each. Each worker is a small graph of its own.

By the end

You can predict how many LLM calls a run will make from the planner's output, and you've changed the cap that keeps cost under control.

The idea

Also called orchestrator-workers by Anthropic and LangGraph. It fits "complex tasks where you can't predict the subtasks needed." Source

In Pattern 3 the three reviewers were written into the graph. Here nobody knows in advance how many sub-tasks there will be; the planner decides at run time. Two LangGraph features make that work:

  • Send. The delegate function returns one Send("worker", {"subtask": …}) per sub-task, so LangGraph starts that many copies of worker, each with its own input.
  • A subgraph as a node. worker is a compiled graph (research → summarise) added with g.add_node("worker", build_worker()). That is the doll inside the doll.

Do it

  1. Run the pattern
    $ make patterns P=pattern_4_hierarchical_decomposition

    The goal is a briefing on all the support a 70-year-old living alone on $1,200 a month could get. The last line tells you what the planner did: Planner created N sub-tasks; N workers reported.

    Predict If the planner made 3 sub-tasks, how many LLM calls did the run make?

    Five: 1 planner + 3 workers (only summarise calls a model; research is a search) + 1 aggregator. In general that's N + 2. Compare with the trace's "LLM calls" count.

  2. Open the inner doll

    In Studio, pick pattern_4_hierarchical_decomposition and submit the default goal (copy it from GOAL in the file). The worker node is a subgraph: expand it to see research → summarise, and watch several workers run at once.

  3. Make the goal bigger

    Give the planner a goal that touches more schemes. In Studio, type it into goal; on the command line, replace GOAL in pattern_4_hierarchical_decomposition.py:

    Prepare a briefing on ALL support a household could get: two grandparents aged 68 and 72, two working adults earning $5,500 a month together, one adult who wants to retrain, and a family that plays sport.
    Check Did the number of sub-tasks go up? What stops it growing without limit?

    The planner probably asked for more sub-tasks, but you'll never see more than four workers: planner returns plan.subtasks[:4]. That one slice is the cost control. Every extra sub-task is one more LLM call, and with a real planner a vague goal can produce a lot of them.

  4. Tighten the cap

    Change plan.subtasks[:4] to plan.subtasks[:2] and run again. Read the briefing: what's missing now? Decide which you'd rather have in production, a cheaper briefing or a complete one, and put the cap back where you want it.
