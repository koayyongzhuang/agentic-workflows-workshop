Sequential Pipeline Assembly Line

A fixed chain of agents. Each one does one job, writes its result into the shared state, and hands over to the next.

By the end

The scenario

A citizen writes to the agency with a long, chatty enquiry. Before anyone can answer it, someone has to pull out the facts, find the policy that applies, and only then write the reply. The pipeline does exactly those three jobs, in that order, every time.

You give itAn enquiry: the citizen's message.
It producesfacts (from intake), policy (from researcher) and the final reply (from drafter).
Calls a modelintake and drafter. researcher only searches the knowledge base.

The idea

Also called prompt chaining by Anthropic and in the LangGraph docs. Use it when "the task can be easily and cleanly decomposed into fixed subtasks." Source

Three stages turn a citizen's enquiry into a reply. Each stage reads the fields before it and writes one new field in PipelineState:

The researcher stage calls no model at all. It runs a search over the knowledge base, because retrieval doesn't need judgement. Using a model only where you need one keeps the pipeline cheap and predictable.

Do it

  1. Run it in Studio and look at each hand-over
    What you're testing. Whether every stage's output really is kept in the state, so you can tell which stage got something wrong.

    In Studio (make studio), pick pattern_1_sequential_pipeline. Paste this into the enquiry field and submit:

    Hi, my father is 72 and lives with me and my wife. Our household income is about $3,900 a month. He needs a wheelchair. What help can we get and what should we do next?

    Click each node in turn and watch facts, then policy, then reply appear in the state.

    Predict How many of the three nodes call a model?

    Two: intake and drafter. researcher runs a search, so it returns in milliseconds while the other two take seconds.

    Think Suppose the reply said per-capita income is $3,900. Which field would you check first?

    facts, written by intake. The father, the user and the wife make 3 people, so per-capita should be $1,300. If facts already has the wrong number, the drafter only copied it. This is why the pattern is "easy to debug": every intermediate result is sitting in the state.

    No Studio? Use the terminal instead

    Run the pattern with this enquiry. The trace's last line reads something like 2 LLM calls · 0 tool calls · path: intake → researcher → drafter.

    $ make patterns P=pattern_1_sequential_pipeline

    To print every field, run this in the container shell:

    python -c "
from lab_2_multi_agent.patterns.pattern_1_sequential_pipeline import build_graph, ENQUIRY
r = build_graph().invoke({'enquiry': ENQUIRY})
for k in ('facts', 'policy', 'reply'):
    print('==', k.upper(), '==', r[k], sep='\n')
"
  2. Add a fourth stage
    What you're testing. How cheap it is to extend a pipeline, and what happens when two stages write the same field one after the other.

    Add a simplifier that rewrites the reply for a reading age of 10. In pattern_1_sequential_pipeline.py, add this function above build_graph:

    def simplifier(state: PipelineState, config: RunnableConfig) -> dict:
    simple = ask_llm("simplifier",
                     "Rewrite this reply for a reading age of 10. Keep every fact, amount and [source].",
                     state["reply"], config)
    return {"reply": simple}

    Then, in build_graph, replace g.add_edge("drafter", END) with:

    g.add_node("simplifier", simplifier)
g.add_edge("drafter", "simplifier")
g.add_edge("simplifier", END)

    Save. Studio reloads the graph; if it doesn't, restart make studio. Open a new thread and submit the same enquiry. The graph now ends with simplifier.

    No Studio? Use the terminal instead 
    $ make patterns P=pattern_1_sequential_pipeline
    Check Two stages now write reply. Why is that allowed?

    They write it one after the other, never in the same step. A state field with no reducer keeps the last value written, so simplifier simply replaces the drafter's text. Three nodes now call a model (the terminal trace says 3 LLM calls). Pattern 3 shows what happens when two nodes write the same field at the same time.
