Orchestrator Concierge

A central agent reads the request, decides what kind it is, and hands it to exactly one specialist desk.

The idea

Name trap. Anthropic and the LangGraph docs call this pattern routing. Their "orchestrator-workers" is a different pattern: the slide's Hierarchical Decomposition. Older versions of the slide called it Coordinator / Dispatcher, which is why the routing node is still named coordinator.

The coordinator node makes one model call. It doesn't write free text: it fills in a small form, the Intent model, whose desk field can only be one of four names. This is structured output. A conditional edge then reads state["desk"] and goes to that node.

Desk = Literal["schemes_desk", "appointments_desk", "complaints_desk", "general_desk"]

class Intent(BaseModel):
    desk: Desk = Field(description="schemes_desk: grants/eligibility; appointments_desk: ...")
    confidence: float

Because the answer can only be a valid desk name, the routing code never has to parse a sentence like "I think this belongs with appointments". Each desk then gets a short, focused prompt for its one kind of request.

Do it

  1. Run the pattern
    $ make patterns P=pattern_2_orchestrator

    The reply starts with the desk that handled it, for example [schemes_desk].

  2. Predict the desk, then test it

    Before running each line, write down which desk you expect.

    python -m lab_2_multi_agent.patterns.pattern_2_orchestrator 'I want to reschedule my appointment'
python -m lab_2_multi_agent.patterns.pattern_2_orchestrator 'I disagree with my rejection'
python -m lab_2_multi_agent.patterns.pattern_2_orchestrator 'What time does the service centre open?'
    Check Where did each one go?

    appointments_desk, complaints_desk, then general_desk. The complaint is the interesting one: the word "rejection" never appears in the desk descriptions. A real model routes it from meaning ("unhappy with a decision"); the offline mock routes by matching words, so it may get this one wrong.

  3. Watch one branch light up

    In Studio, pick pattern_2_orchestrator, type any enquiry into enquiry and submit. Only one desk node runs. Click coordinator and find the desk value it wrote to the state.

  4. Add a fifth desk

    Add a translation_desk in pattern_2_orchestrator.py. Three edits:

    # 1. allow the new value
Desk = Literal["schemes_desk", "appointments_desk", "complaints_desk", "general_desk", "translation_desk"]

# 2. in Intent.desk, add to the description string:
#    "translation_desk: wants information in another language; "

# 3. give it a prompt (add to DESK_PROMPTS)
"translation_desk": "Answer in the language the citizen asks for, then add a one-line English summary.",

    You don't add a node or an edge: build_graph loops over DESK_PROMPTS and wires every desk for you.

    python -m lab_2_multi_agent.patterns.pattern_2_orchestrator 'I need a translation of the energy rebate rules into Malay'
    Think What happens if you do step 3 but skip step 1?

    The node exists, but the model can never choose it: Desk still allows only four values, so translation_desk is never a valid answer. The Literal is what the model is allowed to say; DESK_PROMPTS is what exists. Both have to agree.
