Parallel Fan-Out / Gather Octopus

Several agents work on the same input at the same time. A synthesizer waits for all of them and merges what they found.

The scenario

The agency is about to publish a notice about the Senior Mobility Grant. Before it goes out, it needs three different checks: is it correct, is it easy to read, and is the tone right for citizens? The checks don't depend on each other, so three reviewers do them at the same time, and a synthesizer turns their feedback into a rewritten notice.

You give itA draft: the notice to review.
It producesreviews, one entry per reviewer, and final, the rewritten notice.
Calls a modelEvery reviewer (policy_reviewer, accessibility_reviewer, tone_reviewer) and the synthesizer: four calls, but the three reviews run side by side.

The idea

Also called parallelization (Anthropic). This version is "sectioning": each reviewer checks a different aspect. The other kind, "voting", runs the same check several times. Source

All three reviewers have an edge from START, so LangGraph runs them in the same super-step, concurrently. The synthesizer has an edge from each reviewer, so it waits until all three are done.

Three nodes writing to the same field in the same step is a conflict: whose value wins? The answer is a reducer. reviews is declared with operator.add, so LangGraph appends all three lists instead of overwriting:

class ReviewState(TypedDict, total=False):
    draft: str
    reviews: Annotated[list[str], operator.add]   # parallel writes are appended
    final: str

Do it

  1. Run it in Studio and see the branches run together
    What you're testing. Whether nodes in the same super-step really run at the same time, and how their results end up in one list.

    In Studio, pick pattern_3_parallel_fan_out_gather. Paste this into the draft field and submit:

    Notice: The SMG grant is disbursed subject to means-testing per capita inclusive of all co-residing household members, contingent upon therapist certification. Apply via the portal. Non-compliance with documentary requirements will result in rejection.

    The three reviewers start together. After they finish, reviews holds three entries and synthesizer writes final. Compare it with the draft you pasted.

    No Studio? Use the terminal instead 
    $ make patterns P=pattern_3_parallel_fan_out_gather

    The output ends with 3 reviews gathered.

  2. Break it on purpose
    What you're testing. Why fields that parallel nodes write need a reducer.

    In pattern_3_parallel_fan_out_gather.py, change the reviews line to a plain list, without the reducer:

        reviews: list[str]

    Save. Studio reloads the graph; if it doesn't, restart make studio. Open a new thread and submit the same draft.

    No Studio? Use the terminal instead 
    $ make patterns P=pattern_3_parallel_fan_out_gather
    Predict What happens?

    The run fails with an InvalidUpdateError saying the reviews key can receive only one value per step. Three nodes wrote it in the same super-step and LangGraph refuses to pick one silently. Put Annotated[list[str], operator.add] back before you continue.

  3. Add a fourth reviewer
    What you're testing. What one more parallel branch costs, in time and in money.

    Add one entry to REVIEWERS. Nothing else changes: build_graph wires every reviewer in a loop.

    "translation_reviewer": "Check the notice will translate cleanly into Chinese, Malay and Tamil. "
                        "Flag idioms, jargon and long compound sentences.",

    Save. Studio reloads the graph; if it doesn't, restart make studio. Open a new thread and submit the same draft. Studio's graph now shows four reviewers.

    No Studio? Use the terminal instead 
    $ make patterns P=pattern_3_parallel_fan_out_gather
    Predict Four reviewers instead of three. What happens to the total time?

    It barely changes. The new reviewer runs alongside the other three, so you wait for the slowest one, not for all of them in turn. You do pay for one more LLM call. reviews now has four entries (the terminal says 4 reviews gathered.).
