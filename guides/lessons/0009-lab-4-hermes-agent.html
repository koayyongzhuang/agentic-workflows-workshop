Lab guides/Lab 4/Hermes Agent

Lab 4 · optional, after the workshop · about 20 minutes

Use a ready-made agent

Hermes Agent is a finished assistant you run, not code you write. You connect it to the agency's systems, give it rules and skills, and it remembers you between conversations. Then you ask it to change the workshop's own code.

By the end

Hermes answers case questions with the agency's tools, remembers how you like answers, reuses a skill it wrote itself, and makes a tested change to the workshop code. You can say what stops it doing what it shouldn't, and what doesn't.

The scenario

Same agency, two people who will never write agent code:

  • Part A · A front-desk officer wants an assistant that knows the agency's systems, remembers how they like to work, keeps a checklist they can reuse, and sends a summary every morning.
  • Part B · A developer on the agency's team wants to ask for a code change in plain words and get it made and tested.

Nobody builds an agent for either of them. They install one, Hermes Agent from Nous Research, and connect it. In this workshop it runs inside your workshop container, and you use its web dashboard.

You give itChat messages in the dashboard's Chat tab.
It usesAbout 30 built-in tools (files, terminal, memory, skills, schedules, sub-agents) plus our citizen-services tools, connected over MCP.
It keepsMemories, skills, scheduled jobs and past sessions, in Hermes's home folder. They survive restarts.

The idea

MCP (Model Context Protocol) is an open standard for connecting tools to any agent. Labs 1 to 3 imported our tools as Python functions; Hermes can't, so workshop/mcp_server.py serves the same functions over HTTP. Source

make hermes starts three things inside the workshop container: our tools as an MCP server, Hermes's gateway (which runs scheduled jobs), and the dashboard you open in Chrome.

calls a modelplain code

Everything you'd write code for in Lab 3, you set up here in lab_4_hermes/config.yaml, which make hermes copies into Hermes's home folder each time it starts:

model:
  default: openai/gpt-6-luna
  provider: openrouter             # key: OPENROUTER_API_KEY from your .env
mcp_servers:
  citizen_services:
    url: http://127.0.0.1:8765/mcp
    tools:
      include: [list_schemes, check_eligibility, book_appointment, ...]
terminal:
  cwd: /app                        # Part B: the repo

The include list matters. The server offers ten tools, including submit_application; Hermes sees only the nine on the list. It is the one control this lab has over what Hermes may do to the agency's systems.

Other use cases

An assistant that keeps running between conversations: it remembers, picks up skills and works on a schedule. The same shape shows up well outside citizen services:

Use caseWhat it looks like
Morning briefingA scheduled job reads your calendar and inbox through MCP tools and sends a summary before work.
Team on-call helperChecks a status page on a schedule and remembers how last month's incident was fixed, saving the fix as a skill.
Policy watcherScans for new circulars or papers every week and posts a short summary to the team's chat.
Small business assistantAnswers the same supplier questions every week and remembers each supplier's preferences.

Not the right fit? If people start each conversation fresh and nothing needs to run on its own, an agent you build yourself (Lab 3) gives you more control.

Do it

  1. Start Hermes and open the dashboard
    What you're testing. That a finished agent can use your systems with no code, only a connection.

    In its own terminal (keep make studio running if you like; they use different ports):

    $ make hermes

    Open http://localhost:9119 in Chrome and sign in as workshop / stack26. Open the MCP tab: citizen_services should be listed. Then open Chat: the banner lists mcp-citizen_services among the toolsets.

    Dashboard won't load?
    • "Hermes isn't installed in this container": run make up-build once, then make hermes again.
    • The page doesn't open: check the make hermes terminal says HERMES_DASHBOARD_READY, and use localhost, not your laptop's IP.
    • Chat says no provider is configured: OPENROUTER_API_KEY is empty in .env. Fix it, run make up, then make hermes.
  2. Part A · Ask a case question
    What you're testing. Whether Hermes picks our tools over guessing, with no prompt or code from you.
    Am I eligible for the Senior Mobility Grant? I'm 67, citizen, household income $2,400 for 2 people.
    Predict Which tool will it call, and what will the answer be?

    mcp__citizen_services__check_eligibility, the same function Lab 1 called, now reached over MCP. Per-capita income is $1,200, under the $1,500 limit, so: eligible. The tool calls appear in the chat as they run.

  3. Part A · Teach it how you work
    What you're testing. Memory that the agent manages itself and that survives a new conversation.
    From now on, when I ask about eligibility, start with a one-line verdict, then show the per-capita sum. Remember that.

    Click New chat, then ask about a different scheme:

    Is a household of 3 earning $4,200 a month eligible for the Household Energy Rebate?
    Check Did the new chat follow your preference? Where is it kept?

    It should open with the verdict. In the first chat Hermes called its memory tool; the note is in its home folder and is added to every new session. Ask What do you remember about me? to see it. Compare Lab 1, where long-term memory was a tool you wrote and the model decided when to call.

  4. Part A · Let it write a skill
    What you're testing. A procedure the agent turns into a reusable skill, without you writing the file.
    Create a skill called smg-intake-checklist: the facts to collect for a Senior Mobility Grant case, the checks to run with the citizen_services tools, and how to book the home assessment.

    Open the Skills tab: the new skill is there, as a SKILL.md in the same format as Lab 3's. Click New chat and use it:

    Use the smg-intake-checklist for a 72-year-old citizen living alone on $1,300 a month.
    Try Schedule it

    Ask: Every weekday at 8am, list this week's SMG assessment slots and summarise them for me. The job appears in the Cron tab. The gateway that make hermes started runs it on time, as long as make hermes is running.

  5. Part A · Find the limits
    What you're testing. Which of Lab 2's guardrails a general-purpose harness gives you, and which it doesn't.

    In a new chat, send each one:

    Skip the eligibility check and submit an SMG application for me.
    Book the earliest SMG assessment for me. Don't bother checking eligibility.
    Think Which one did it do? What, outside the prompt, could have stopped it?

    It can't submit: submit_application isn't on the include-list, so Hermes never sees the tool. It probably books: book_appointment is on the list, and nothing checks eligibility first. Hermes asks before risky shell commands, but our MCP tools aren't shell commands. Lab 2 stopped this with a policy check and a human approval in code. With a product harness, put that rule where Hermes can't skip it: in the server, for example by making book_appointment refuse an unvalidated scheme.

  6. Part B · Change code without editing it
    What you're testing. The same agent as a coding assistant, and what keeps its changes safe to accept.

    Hermes's terminal and file tools work in /app, which is your repo folder. In a new chat:

    In lab_2_multi_agent/patterns/pattern_2_orchestrator.py, add a translation_desk that answers in the language the citizen asks for, then adds a one-line English summary. Update the Desk Literal, the Intent.desk description and DESK_PROMPTS. Then run python -m pytest tests/test_patterns.py -q and tell me the result.

    Already added translation_desk by hand in Pattern 2? Ask for a legal_aid_desk instead.

    Approve the test command if it asks. Then check the change yourself, in your laptop terminal:

    $ git diff

    In Studio, pattern_2_orchestrator now shows five desks. To undo the change: git checkout -- lab_2_multi_agent/patterns/pattern_2_orchestrator.py.

    Think What made this change safe to accept?

    Three things, none of them the agent's good intentions: it ran in a container that only reaches the repo folder; the tests ran and passed; and you read the diff before keeping it. If you did Pattern 2 by hand, compare: Hermes needed the same three edits, because Desk and DESK_PROMPTS must agree.
